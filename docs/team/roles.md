## 4. 看板（建议用群公告/在线表格，列定义）

| 列 | 含义 | 进入条件 |
| --- | --- | --- |
| 待办 | 已确认、未开始 | 有负责人与截止日期 |
| 进行中 | 正在做 | 同一人最多 2 项 |
| 评审中 | 产出已提交、待评审 | 附文档链接与版本号 |
| 完成 | 评审通过或测试通过 | 有证据（文件/数据/截图） |

## 5. 工作纪律

1. 数据：raw 只读；测试后当天把文件放 `data/raw/` 并跑 `validate.py`；模拟数据文件名带 `SIM`。
2. 代码：能复现（命令写进 README/文档）；提交前自测；不提交密钥与大数据文件。
3. 文档：中文为主，术语首次出现给英文；数字给单位与来源。
4. 安全：通电旋转测试双人、防护罩、急停可用；违规一次全组复盘。
5. 汇报：每周四前把进展/问题发给 A，A 汇总周报。

## 6. 交接与备份

- 关键文件（设计图、BOM、确认单、测试记录）除 Git 外，每周五打包备份到项目网盘/群文件；
- 负责人变更时，交接清单：文档 + 代码 + 数据 + 待办 + 外部联系人；
- 仓库每完成一个里程碑打 tag（如 `m0.4`）。
